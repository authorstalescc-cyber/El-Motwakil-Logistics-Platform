## 3. `build_system.py` — النظام الأساسي

**المخرج:** `المتوكل - نظام إدارة النقل والتخليص.xlsx`.

### 3.1 اصطلاحات التصميم (ثوابت عامة، أسطر 17–56)

- **الألوان:** `NAVY=FF15355B`, `GOLD=FFC9A227`, أخضر (إيراد)، أحمر (مصروف)، تركواز، بنفسجي.
- **القاعدة الذهبية للألوان:**
  - `INPUT_FILL="FFFFFDF3"` (أصفر فاتح) = **خلية إدخال** يكتب فيها المستخدم.
  - `CALC_FILL="FFEDF2F8"` (أزرق فاتح، خط مائل) = **خلية معادلة** محسوبة تلقائيًا — لا يُكتب فيها.
- **الخط:** Arial. **الصيغ الرقمية:** `MONEY='#,##0.00 "ج.م"'`, `PCT='0.0%'`, `DATEF='DD/MM/YYYY'`.
- **الشبكة:** `DATA_ROWS=2200` صف جاهز لكل شيت إدخال، الترويسة صف 3 (`HDR_ROW`)، أول صف بيانات 4 (`DATA_START`)، آخر صف 2203 (`DATA_END`). صفّان 1–2 = البانر.

### 3.2 المحرّك: `build_entry_sheet(...)` (أسطر 252–302)

الدالة العامة اللي تبني كل شيت إدخال من مواصفة أعمدة. كل عمود = dict فيه `{header, group, kind, numfmt}` حيث `kind ∈ {input, formula, serial}`:
- **`serial`** (عمود "م"): ترقيم تلقائي `=IF($key="","",COUNTA(...))` — يترقّم لوحده لما عمود المفتاح (التاريخ) يتملّى.
- **`formula`**: تُلَفّ المعادلة في `=IF($key="","",<formula>)` عشان الصفوف الفاضية تفضل فاضية.
- تربط القوائم المنسدلة، العرض، صف الإجماليات، وتُنهي الشيت (RTL، تجميد `A4`، فلتر، إخفاء gridlines).

### 3.3 القوائم المنسدلة (data validation، أسطر 191–240)

ستة قوائم مصدرها شيت **الإعدادات**، كل قائمة في عمود:
| القائمة | العمود |
|---------|--------|
| التصنيفات | D |
| الشركات | E |
| الجهات | F |
| السائقين | G |
| أصحاب السيارات | H |
| العملاء | I |

سقف كل قائمة `LIST_MAX=200`. named ranges: `نسبة_القيمة_المضافة → الإعدادات!$B$5`, `سنة_التقارير → $B$6`, و`قائمة_<name>` لكل قائمة.

### 3.5 معادلات الشيتات الأساسية

**البوالص** (`bawalis_formula`, أسطر 349–365) — كلها بـ `N()` لتحويل الفاضي لصفر:
```
إجمالي التحصيل = نولون + تحويلة + بياتة(تحصيل)
باقي          = إجمالي التحصيل − دفعة              ← لا يستخدم الخصم (ملاحظة مقصودة)
إجمالي المصروف = SUM(دور سواق : جاز)
الباقي من العهدة = عهدة − إجمالي المصروف
صافي السيارة   = نولون − إجمالي المصروف
ربح/خسارة %    = (نولون − إجمالي المصروف) / نولون
```

**شامل** (`shamil_formula`, أسطر 501–516):
```
قيمة مضافة    = ROUND((نولون + بيانات/عطالات) × نسبة_القيمة_المضافة, 2)
إجمالي الفاتورة = نولون + بيانات + ق.مضافة − خصم أ ت ص + الإيصالات
إجمالي الحساب  = إجمالي الفاتورة − الدفعات
إجمالي ربح     = نولون − نولون فعلي − مصروف
```

> هذه المعادلات هي **نفسها** المطبّقة في `Calc.php` بنسخة الويب. أي تعديل في مكان لازم يتزامن مع الآخر. راجع [06-business-logic.md](06-business-logic.md).

## 4. `build_daily_closing.py` — التقفيل اليومي

**المخرج:** `المتوكل - تقفيل اليومية.xlsx`. يتتبّع **عُهدة** الشركة النقدية اليومية.

### 4.1 ★ آلية الربط بالنظام الأساسي (أسطر 30–55, 156–166)

الـ docstring يصفه كأنه "External Link"، لكن **التطبيق الفعلي يضمّن القيم، مش روابط حيّة:**
- عند البناء يفتح الأساسي read-only: `load_workbook(MAIN_PATH, data_only=True, read_only=True)` (سطر 45).
- يقرأ أعمدة القوائم المشتركة من شيت الإعدادات في الأساسي — **E=الشركات, F=الجهات, H=أصحاب السيارات** (rows 4–203) في `cache_vals`.
- يكتبها **كقيم منسوخة ثابتة** في أعمدة الإعدادات H/I/J بملف التقفيل.
- **النتيجة:** لا اعتماد على external-link، ولا رسالة "update links" عند الفتح.

**شرط نفس المجلد:** `DIR = "/Users/karimmokhtar/المتوكل"` مكتوب صراحةً (hard-coded). لازم الملفان في نفس المجلد. تحديث القوائم بعد البناء = إعادة تشغيل `sync_lists.py` (مش عبر روابط Excel).

### 4.2 ★ قاعدة "العهدة تلغي نفسها في التقفيل"

النموذج المحاسبي الأساسي للملف، في شيت **سجل اليومية** (أسطر 301–361). العهدة المسلّمة للرحلة = مبلغ يجب تسويته **نفس اليوم**، يُعامَل كبند مصروف يُخصَم من العهدة المتاحة، فـ"يلغي نفسه" في التقفيل:
```
إجمالي العهدة المتاحة (E) = باقي عهدة سابق (C) + العهدة المستلمة (D)
إجمالي العهد (الرحلات) (F) = SUMIFS لعُهد رحلات اليوم
إجمالي الإيصالات (G)      = SUMIFS لإيصالات اليوم
إجمالي المصروف (I)        = العهد + الإيصالات + مصروفات أخرى
رصيد مُرحَّل لليوم التالي (J) = المتاح (E) − المصروف (I)
```
- صف 1: `باقي عهدة سابق = رصيد_افتتاحي` (named range)؛ كل صف تالي يسحب رصيد الصف السابق `=N($J{r-1})`.
- رصيد مُرحّل سالب (عجز عهدة) يُميّز بالأحمر شرطيًا.

### 4.3 الشيتات (أسطر 601–606)

`تقفيل اليوم, سجل اليومية, العهد والرحلات, الإيصالات, الإعدادات, الدليل`.
- **الإعدادات:** الرصيد الافتتاحي (`رصيد_افتتاحي`, B4). قوائم محلّية (شركة الشحن، توكيل، الميناء — مبذورة بموانئ مصرية وخطوط ملاحة) + قوائم منسوخة من الأساسي (H/I/J). Validation بـ `errorStyle="warning"` (يسمح بالكتابة خارج القائمة).
- **العهد والرحلات:** سجل مستمر، 10 أعمدة، 2000 صف.
- **الإيصالات:** سجل مستمر، 4 أعمدة، 2000 صف.
- **سجل اليومية:** 500 صف — قلب التقفيل (§4.2).
- **تقفيل اليوم:** نموذج جاهز للطباعة — تكتب تاريخ في `B4` (افتراضي `=TODAY()`) فيظهر تقفيل اليوم كامل عبر `INDEX/MATCH` وأعمدة مساعدة مخفية.

## 5. `migrate.py` — نقل البيانات القديمة

يقرأ `old-system-data.xlsx` (`OLD`) ويكتب في النظام الأساسي المُولّد (`NEW`). يُشغَّل **بعد** `build_system.py`.

- **تنظيف** (أسطر 14–31): `is_err` يسقط أخطاء Excel، `clean` يطبّع الفاضي، `num` يحوّل لرقم-أو-صفر.
- **البوالص** (44–77): `BAW_MAP` يربط أعمدة قديمة → ترويسات جديدة. تحويلان مهمّان:
  - الأعمدة الثلاثة "م اخرى" القديمة تُجمَع في عمود `م أخرى` واحد.
  - عمود `خصم` القديم يُقرأ ويُتتبّع (308,000 ج.م) لكن **لا يُدخَل في حساب** — يُبلَّغ للتدقيق فقط.
- **المولدات** (80–93): `مولدات ايجى كول ` (لاحظ المسافة الأخيرة) + `مولدات الشجيع`.
- **العملاء والموردين** (95–106): من شيت `اجمالي`.
- **الكتابة** (114–165): `header_map` يحدّد الأعمدة بنص الترويسة (مقاوم لإعادة الترتيب)؛ `clear_sample` يمسح العيّنة **مع الحفاظ على المعادلات** (يتخطّى أي قيمة تبدأ بـ `=`).
- **إعادة بناء القوائم** (170–204) من البيانات الحقيقية (سقف 200).
- الأعداد المنقولة: ~1728 بوليصة، 46 ايجي كول، 3 الشجيع، 47 عميل، 8 موردين.

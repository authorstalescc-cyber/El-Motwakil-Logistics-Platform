## 2. ★ نموذج العمل المحاسبي (اتجاه المال معكوس!)

> **تحذير حاسم:** اتجاه المال في هذا النظام **عكس المتوقّع في أنظمة المحاسبة العادية.**
> نسيان ده هيقلب الإشارات ويكسر التقارير.

**القاعدة:**

- **الدين على الشركة لصالح العملاء** — مش العملاء عليهم دين للشركة.
- **"الدفعات / المتحصلات" (`collections`, `bill_payments`, `payments`) = مبالغ صادرة من الشركة للعملاء** — يعني **مدفوعات** مش متحصّلات.
- **"المتبقي / الدين" (`remaining`, `outstanding`, `debt`, `account_total`) = ما على الشركة للعملاء** (التزام)، مش مبالغ مستحقّة لها.

**بالتفصيل في `Metrics::totals()`:**

| المؤشّر | المعنى الحقيقي |
|---------|----------------|
| `collections` (المدفوعات) | مبالغ **دفعتها الشركة** للعملاء/أصحاب البيان = `bill_payments + shamil.payments + takhlis.payments + generators.payments`. |
| `outstanding` (المتبقي) | **دين على الشركة** للعملاء = `bawalis.remaining + shamil.account_total + takhlis.remaining + generators.remaining`. |
| `revenue` (الإيراد) | `bawalis.freight + shamil.invoice_total + takhlis.total_statement + generators.freight`. |
| `expenses` (المصروفات) | `movements.total_expense + shamil.expense + takhlis.expenses`. |
| `custody` (العهدة) | Σ `bawalis.custody`. |

**نتيجة مهمة:** التقارير **تشغيلية بلا ربح نهائي**. "صافي الأرباح" في اللوحة = مجموع "صافي السيارة" = نولون − مصروفات التشغيل، وده **مش الربح النهائي للشركة**. ربح الوساطة الحقيقي بيظهر فقط في وحدة **شامل** (`profit_total = freight − actual_freight − expense`).

راجع تفاصيل المعادلات في **[06-business-logic.md](06-business-logic.md)**.

## 3. العلاقة: وكيل ↔ شركة

- **الوكيل (`agent`) = العميل الحقيقي** للمتوكل (الشخص/الكيان اللي بيتعامل مباشرة).
- **الشركة (`company`) = الجهة المستفيدة** (لصالحها يُستخرج الإذن/الشهادة).
- العلاقة **many-to-many**: وكيل واحد يمثّل شركات كتير، وشركة واحدة ممكن يمثّلها أكثر من وكيل. (جدول الربط `agent_company`.)
- **دليل الوكلاء والشركات (`/directory`) عرض فقط** — بروفايلات تُجمَّع بمطابقة الاسم النصّي من الأذونات والفواتير والأرصدة.

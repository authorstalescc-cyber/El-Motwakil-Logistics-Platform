# الخطة 07 — العرض والوصولية والهاتف والطباعة

**الحالة:** in_progress — 07-A و07-C مكتملتان؛ الجزء الآلي من 07-B مكتمل

**الأولوية:** P1–P2

**التقدير الأولي:** 4–6 أيام

**الاعتماد:** الخطة 04

## الهدف

بناء واجهة متسقة ومقروءة تعمل بلوحة المفاتيح والهاتف والطباعة، بتغيير تدريجي لا يعيد كتابة التطبيق دفعة واحدة.

## نطاق التنفيذ

1. توكنات مشتركة للون والخط والمسافة والحواف والحركة، مع cache busting للأصول.
2. مكونات صغيرة: زر، شارة، حقل، رسالة، حالة فارغة، pagination، جدول، modal، ورأس صفحة.
3. نقل inline CSS/JS عند لمس الوحدة، لا حملة حذف جماعية عالية المخاطرة.
4. labels وعلاقات ARIA في HTML، وعدم الاعتماد على JavaScript لإصلاح markup بعد التحميل.
5. focus trap وEscape وإرجاع التركيز لكل حوار، واحترام `prefers-reduced-motion`.
6. عدم الاعتماد على اللون وحده في الديون والأرصدة والحالات.
7. أهداف لمس مناسبة، وفلاتر وجداول من 320px حتى سطح المكتب، وحالات اتصال/إرسال واضحة للمندوب.
8. هيكل طباعة مشترك للترويسة والتذييل والتوقيعات وA4، مع بقاء بيانات كل مستند مستقلة.

## خارج النطاق

- إعادة branding أو dark mode ما لم يطلبهما المالك لاحقًا.
- تغيير كثافة كل الشاشات قبل اختبار مهامها.

## حزم التنفيذ الصغيرة

### 07-A — أساس بصري ومكونات

- اعتماد tokens ومكونات الزر/الحقل/الرسالة/الحالة الفارغة في شاشة واحدة.
- فحص التباين، focus، وحالات loading/disabled قبل التوسع.
- **الموجة الأولى المنفذة:** ثُبت أن CSS الحالي يملك أصلًا توكنات اللون والخط والحواف، وحلقة `focus-visible`، و`prefers-reduced-motion`، ومكونات مشتركة للزر والحقل والرسالة والحالة الفارغة؛ لذلك لم تُنشأ طبقة تصميم مكررة.
- شاشة الدخول أصبحت تستخدم `main`، وربطًا صريحًا بين `label` والحقول، و`autocomplete` المناسب لمدير كلمات المرور، وتعلن `aria-busy` أثناء الدخول. نُقل CSS/JS المضمّن عند لمس الشاشة إلى الأصول المشتركة/ملف `login.js` مستقل.
- أضيف cache busting لـCSS في التخطيط والدخول ولـJavaScript شاشة الدخول، وأضيف `bin/verify_accessibility_foundation.php` بعدد 47 تحققًا بنيويًا بلا قاعدة، يغطي الآن الدخول والمصروف والأساس المشترك.
- نُقلت تنسيقات وسلوك تخصيص المصروف للمندوب من القالب إلى CSS مشترك و`expenses-form.js`، وأصبحت علاقات `label` وحقول الدخول والمصروف صريحة في HTML. يظل نفس القرار المالي والسلوك الوظيفي بلا تغيير.
- **فحص القبول:** نجح `verify_accessibility_ui.py` على قاعدة معزولة في الدخول والمصروف: لوحة المفاتيح، رجوع التركيز، سلوك تخصيص المندوب، عدم التمدد، وثماني عينات تباين؛ أقل نسبة مقاسة `5.54:1`. تمت مراجعة اللقطتين بصريًا، ولا أخطاء HTTP أو console.
- **حالة 07-A: مكتملة.** لم تُنشأ طبقة تصميم مكررة ولم يُعمم تغيير بصري خارج الشاشتين.

### 07-B — الوصولية والتجاوب

- اختبار لوحة المفاتيح وقارئ الشاشة وzoom 200% على الدخول والمصروف والفاتورة.
- اختبار 320px و768px و1440px، مع عدم استخدام اللون وحده للدين أو الحالة.
- **الجزء الآلي مكتمل:** `verify_responsive_ui.py` يختبر الدخول والمصروف والفاتورة عند `320/720/768/1440px`؛ عرض `720px` هو بروتوكول إعادة التدفق المكافئ لـzoom 200% من سطح مكتب 1440px. يتحقق من عدم تمدد المستند، بقاء الإجراء الأساسي داخل العرض، أهداف لمس `44px`، فتح/غلق القائمة، الأسماء الدلالية، ترتيب لوحة المفاتيح في الفاتورة، وأسماء البنود المضافة ديناميكيًا.
- أصلح الفحص عيوبًا فعلية بدل إخفائها: حقول دخول بارتفاع `38px`، شبكة مصروف من عمودين تقص المحتوى عند 320px، شريط جانبي مغلق يوسّع لقطة 320px إلى 463px، وشريط علوي يدفع زر الخروج خارج الشاشة. بعد الإصلاح صارت لقطتا المصروف والفاتورة بعرض 320px فعلًا.
- أضيفت روابط `label` صريحة و`aria-label` لبنود الفاتورة الثابتة والديناميكية، مع نص حالة ظاهر لا يعتمد على اللون وحده.
- **المتبقي لإغلاق 07-B:** مرور يدوي بقارئ شاشة فعلي (VoiceOver/NVDA). الفحص الآلي يثبت الأسماء والترتيب لكنه لا يدّعي محاكاة قارئ الشاشة نفسه.

### 07-C — الطباعة وبوابة المندوب

- قالب طباعة A4 مستقل، ثم اختبار البوابة على اتصال بطيء وانقطاع أثناء الإرسال.
- لا يُقبل أي قص أو تداخل أو فقد لزر الإجراء الأساسي.
- **الحالة: مكتملة آليًا وبصريًا.** أضيف `bin/verify_print_portal_ui.py` بحارس اسم قاعدة معزولة. ينشئ إذنًا وفاتورة ومندوبًا مؤقتًا، ويثبت أن كشف الإذن والفاتورة يخرجان في صفحة A4 واحدة لكل مستند، وأن أدوات الشاشة تختفي، ولا يوجد قص أفقي أو تداخل بين كتل المحتوى.
- روجع ملفا PDF الناتجان بصريًا بعد تحويل الصفحة الأولى إلى صورة: الترويسة والجداول والإجماليات والتذييل داخل الورقة بلا قطع. صار رمز QR الخارجي يختفي بأمان إذا فشل تحميله بدل ظهور رمز صورة مكسورة في المستند.
- اختُبرت بوابة المندوب عند `320px` باتصال ذي `350ms` latency وسرعات محدودة، ثم بانقطاع قبل الإرسال وانقطاع أثناء `fetch`. ظلت القيم محفوظة محليًا، وعاد زر الإجراء لحالته، ونجحت إعادة المحاولة بنفس `client_token` مع صف واحد فقط في القاعدة.
- كشف الاختبار أن مكونات `display:flex` كانت تتجاوز السمة `hidden` وتعرض شريط شبكة/مسودة فارغًا في الاتصال السليم. أضيفت قاعدة `[hidden]{display:none!important}` داخل CSS بوابة المندوب فقط، بلا تغيير في المعادلات أو الصلاحيات.

### 07-D — التعميم التدريجي

- تعميم المكونات وحدةً وحدة، مع screenshot diff ومراجعة رحلة مستخدم قبل كل موجة.
- رجوع CSS/JS عبر cache-busted asset version دون تعديل البيانات.

## بوابة القبول

- فحص آلي ويدوي للدخول والإذن والمصروف والفاتورة والتقفيل وبوابة المندوب. التغطية الآلية الحالية تشمل الجميع عدا رحلة التقفيل الكاملة، ويظل قارئ الشاشة مرورًا يدويًا مطلوبًا.
- لوحة مفاتيح فقط، zoom 200%، عرض 320px، وطباعة PDF بلا قطع أو تداخل.
- لا يفقد أي تغيير بصري معلومة أو إجراءً كان متاحًا.

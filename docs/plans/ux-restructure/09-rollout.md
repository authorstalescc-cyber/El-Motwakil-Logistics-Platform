# الخطة 09 — الإطلاق والتوثيق والرجوع

**الحالة:** pending

**الأولوية:** P2 ومستمر

**الاعتماد:** يطبق مع كل خطة

## الهدف

إطلاق تغييرات صغيرة قابلة للرصد والرجوع، مع توثيق يعكس النظام الفعلي.

## نطاق التنفيذ

1. تغييرات مستقلة لكل خطة أو وحدة، بلا خلط refactor بصري مع منطق مالي.
2. checklist قبل الدمج: اختبارات، قياسات، نسخة احتياطية، rollback، ومراجعة صلاحيات.
3. تجربة على قاعدة معزولة ثم مستخدم محدود أو نافذة تشغيل قصيرة قبل التعميم.
4. مراقبة الأخطاء وزمن الطلب والاستعلامات الفاشلة ومحاولات الدخول بعد الإطلاق.
5. rollback مستقل للكود والترحيل، مع عدم حذف عمود/جدول في نفس إصدار نقله.
6. تحديث `docs/08-frontend.md` و`docs/09-setup-operations.md` ووثائق الأدوار والاستعادة.
7. سجل قرار لأي استثناء مالي أو أمني أو UX.

## حزم التنفيذ الصغيرة

### 09-A — حزمة الإصدار

- تحديد نطاق التغيير، مالك التنفيذ، المخاطر، خطة الرجوع، واختبارات 08 المطلوبة.
- منع خلط refactor بصري مع تعديل مالي في الإصدار نفسه.

### 09-B — إطلاق مراقب

- نسخة احتياطية واستعادة عند الحاجة، ثم تجربة على قاعدة معزولة وحساب محدود.
- مراقبة الأخطاء، p95، رفض الصلاحيات، وتكرار POST خلال نافذة محددة.

### 09-C — قرار التعميم أو الرجوع

- مقارنة الأرصدة والcounts والرحلات مع baseline؛ توثيق أي انحراف وتفسيره.
- التعميم فقط بعد اجتياز البوابات؛ rollback للكود مستقل عن rollback للترحيل.

### 09-D — إغلاق وتعلم

- تحديث وثائق التشغيل والأدوار والاستعادة، وتسجيل ما نجح وما يحتاج موجة لاحقة.

## بوابة القبول لكل إطلاق

- backup صالح واستعادة مجربة عندما توجد كتابة schema/data.
- smoke suite ناجحة قبل وبعد.
- مقارنة الأرصدة والcounts المرجعية.
- لا ارتفاع غير مفسر في الزمن أو الأخطاء أو رفض الصلاحيات.
- مالك واضح للrollback ومدة مراقبة محددة.

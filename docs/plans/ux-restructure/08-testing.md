# الخطة 08 — الاختبارات ورحلات الاستخدام

**الحالة:** in_progress — 08-A و08-B و08-C الآلية مكتملة؛ 08-D منفذة محليًا وأول تشغيل بعيد لـCI متبقٍ

**الأولوية:** P1

**التقدير الأولي:** 3–5 أيام للبنية الأولى، ثم مستمر

**الاعتماد:** يبدأ مع الخطة 01

## الهدف

تحويل سكربتات التحقق الحالية إلى بوابة واحدة تمنع رجوع الأخطاء الأمنية والمالية وتجارب الاستخدام المكسورة.

## نطاق التنفيذ

1. runner واحد لسكربتات `verify_*.php` يعيد exit code صحيحًا ويلخص النتائج.
2. قاعدة اختبار منفصلة وfixtures منزوعة الحساسية، مع حارس يمنع التشغيل على قاعدة الإنتاج.
3. اختبارات auth/CSRF/role لكل route action، واختبارات عدم كشف الأسرار والمرفقات.
4. اختبارات installer/update/failure/recovery وmigration idempotency.
5. اختبارات invariants للحسابات، والحذف والعكس، والأيتام، والتزامن.
6. اختبارات متصفح للرحلات الخمس وحفظ القيم والفلاتر والتركيز والتجاوب.
7. smoke suite سريعة لكل تغيير وfull suite قبل الإطلاق.
8. تشغيل آلي محلي أولًا ثم CI عند تثبيت بيئة المستودع.

## حزم التنفيذ الصغيرة

### 08-A — runner وحارس البيانات

- **الحالة:** مكتملة للبنية الأولى.
- `php bin/run_verifiers.php` يكتشف كل `verify_*.php`، ويرفض أي فاحص جديد غير مصنف، ويعرض نتيجة كل ملف وملخصًا نهائيًا. يعيد `0` عند النجاح، و`1` عند فشل فاحص، و`2` عند رفض الحارس أو خطأ الاستخدام.
- الوضع الافتراضي `safe` لا يفتح اتصال قاعدة بيانات؛ يشغّل الفاحصات المصنفة `بلا قاعدة` فقط ويتخطى الباقي بوضوح.
- عرض التصنيف كاملًا دون تشغيل: `php bin/run_verifiers.php --list`. التصنيفات تميّز: بلا قاعدة، قراءة، كتابة مع `rollback`، كتابة بتنظيف صريح، قاعدة معزولة فقط، وحذف/إعادة إنشاء.
- تشغيل فاحصات القاعدة يتطلب قاعدة مجهزة مسبقًا واسمًا صارمًا عبر:

  ```bash
  ALMOTAWAKEL_TEST_DB=almotawakel_test_<suffix> php bin/run_verifiers.php --profile=isolated
  ```

  الحارس يرفض الاسم الفارغ أو أي اسم لا يطابق `^almotawakel_test_[a-z0-9_]{6,48}$` قبل تشغيل أي فاحص. الـrunner لا ينشئ ولا يحذف قاعدة تلقائيًا.
- أضيف profile باسم `ci` لنقطة البداية الفارغة. يشغّل فقط الفاحصات الحتمية التي تنشئ عينتها أو تقبل غيابها، مع إبقاء `isolated` للتدقيق الأوسع على نسخة بيانات تشغيل منزوعة الحساسية. يعرض `--list` صلاحية كل فاحص لـCI الفارغ وسبب الاستبعاد.
- الفاحصات الخمسة المستبعدة من `ci` هي: دمج الأرشيف، سعة الحركة، الإدخال السريع، v29، وv31؛ لأنها تفترض عينات تشغيل محددة. لا تُعرض كنجاح صوري ولا تمنع تثبيتًا جديدًا سليمًا، وتبقى ضمن دين اختبار صغير لتحويلها لاحقًا إلى fixtures ذاتية.
- `verify_installer.php` و`verify_v41.php` و`verify_restore.php` تملك كذلك حارسًا داخليًا وقد ترفض قاعدة العمل بـ exit `2`. بقية فاحصات القاعدة يحميها الـrunner مركزيًا، بما فيها فاحصات `rollback`؛ فلا يُعامل rollback كبديل للعزل.
- `verify_v33.php` و`verify_v34.php` ينظفان fixtures صراحة لا بمعاملة جامعة، و`verify_v41.php` قد يترك fixture إذا انقطع قبل التنظيف؛ لذلك لا تعمل إلا على القاعدة المعزولة. `verify_restore.php` يحذف قاعدة الاختبار ويعيد إنشاءها، وهو متخطى حتى في الوضع المعزول ما لم يُمرر تأكيد مزدوج مطابق للاسم:

  ```bash
  ALMOTAWAKEL_TEST_DB=almotawakel_test_<suffix> php bin/run_verifiers.php \
    --profile=isolated --include-recreate \
    --confirm-recreate=almotawakel_test_<suffix>
  ```
- لتشغيل مجموعة محددة أضف `--only=verify_v40.php,verify_v41.php`. الأسماء غير الموجودة أو غير المصنفة تُرفض بدل التجاوز الصامت.
- يضم profile الآمن الآن أيضًا `verify_accessibility_foundation.php`: بوابة بنيوية من 47 تحققًا لأساس العرض والوصولية والكاش، إلى جانب مصفوفة الصلاحيات وعقد النماذج.
- صُنّف `verify_v43.php` و`verify_v44.php` ككتابة مع `rollback` لا تعمل إلا في profile المعزول. حُدث فاحص المثبّت ليتعرف إلى v44 ويضع probe الفشل في v45؛ اجتازت الفاحصات الثلاثة القاعدة المعزولة.

### 08-B — مصفوفة الصلاحيات والمال

- **مصفوفة الصلاحيات: مكتملة.** أضيف `bin/verify_access_matrix.php` كاختبار وحدة/بنية بلا `bootstrap` وبلا اتصال قاعدة. يثبت الأدوار الخمسة، وتسجيل كل route حساس على handler المتوقع، وتطبيق `Access::enforce` في `Router` قبل الكنترولر، ونتيجة السماح/المنع لكل دور.
- التغطية الحالية تشمل النسخ الاحتياطي، المستخدمين ومفاتيح AI، الإعدادات، التحصيل وحذفه، التقفيل وإعادة الفتح، عهدة المكتب، إيداعات كروت المكتب، فواتير الأذونات، العكس من سجل المراجعة، وعينات كتابة التشغيل والقراءة.
- التشغيل: `php bin/run_verifiers.php --only=verify_access_matrix.php` ضمن profile `safe`، وأي انحراف في route أو handler أو قاعدة سماح/منع يعيد exit `1`.
- **الثوابت المالية والتزامن: مكتملة ضمن الحزمة المعزولة القائمة.** `verify_v35.php` و`verify_v39.php` و`verify_v42.php` تثبت المعادلة المعتمدة: التنزيل والمرتجع بلا أثر خزنة، والمصروف المعتمد يخصم يوم صرفه، مع تطابق رصيد الكارت والسماح بالسالب. `verify_v41.php` يثبت بسباق حقيقي اعتمادًا وتسويةً متزامنين، ومنع التكرار، وسياسة الحذف، وصفر أيتام، وعودة اللقطة المالية بعد التنظيف.
- `verify_v31.php` يثبت عكس التحصيل وإعادة رصيد الفاتورة وتسجيل الأثر في سجل العمليات. كل هذه الفاحصات مصنفة في runner ولا تعمل إلا عبر profile معزول؛ ويظل `verify_v41.php` بحارس داخلي إضافي.
- **حالة 08-B:** مكتملة. لا يعني ذلك اكتمال اختبارات المتصفح وCI في 08-C/08-D.

### 08-C — المتصفح والرحلات

- **الحالة الآلية:** مكتملة.
- اختبارات الرحلات الخمس، التبويبات، حفظ السياق، التركيز، 320px والطباعة.
- حفظ artifacts عند الفشل فقط، مع redaction للبيانات الحساسة.
- **الحزمة الموحدة منفذة:** `bin/run_browser_verifiers.py` يشغّل بالتتابع خمسة فاحصات ذاتية التجهيز، يتوقف عند أول فشل، ويلخص النتيجة. يرفض أي قاعدة لا تطابق `almotawakel_test_*` وأي عنوان خادم ليس `localhost/127.0.0.1`، ويدعم `--list` و`--only`.
- `verify_forms_feedback_ui.py` يغطي التبويبات وحفظ القيم وPRG والعودة الآمنة ومنع الإرسال المالي المزدوج، وأصبحت علامة fixture عشوائية كي يقبل الفحص إعادة التشغيل في القاعدة المعزولة. `verify_accessibility_ui.py` يغطي الدخول والمصروف والتباين ولوحة المفاتيح، و`verify_responsive_ui.py` يغطي الدخول والمصروف والفاتورة عند `320/720/768/1440px`.
- `verify_print_portal_ui.py` يغطي ورقتي الإذن والفاتورة A4، وواجهة المندوب عند 320px واتصال بطيء، والانقطاع قبل الإرسال وأثناءه، وحفظ المسودة، وإعادة المحاولة idempotent. يحفظ PDF/لقطات النجاح فقط عند ضبط `UX07_CAPTURE_DIR`، ويلتقط الفشل مؤقتًا.
- `verify_workflows_ui.py` يغطي رحلة مترابطة: إصدار فاتورة، تحصيل جزئي وتخصيصه، عكس التحصيل وعودة الرصيد، تحصيل نقدي بلا تخصيص، مطابقة التقفيل، قفل اليوم، منع كتابة مالية مع حفظ القيم، إعادة الفتح من تبويب آخر، ثم نجاح إعادة المحاولة مرة واحدة.
- كشف الفحص خطأ UX ماليًا حقيقيًا: مربع «التخصيص التلقائي» كان يعود محددًا بعد رفض نموذج أُرسل وهو غير محدد. صار العرض يقرأ القيمة القديمة عند الفشل، فلا تغير إعادة المحاولة قرار المستخدم.
- **نتيجة القبول بتاريخ 2026-07-20:** نجحت الحزمة الموحدة `5/5` من تثبيت معزول فارغ؛ ونجح مستندا PDF في صفحة واحدة لكل منهما، بلا استجابات HTTP فاشلة أو أخطاء console غير متوقعة.
- `bin/run_browser_suite.py` يبدأ خادم PHP المحلي، ينتظر جاهزيته، يشغّل الحزمة، ثم يوقفه حتى عند الفشل ويعرض ذيل سجل الخادم عند الحاجة. التشغيل بأمر واحد بعد تجهيز القاعدة وضبط البيئة:

  ```bash
  ALMOTAWAKEL_TEST_DB=almotawakel_test_<suffix> \
  ALMOTAWAKEL_E2E_URL=http://127.0.0.1:8795 \
  python bin/run_browser_suite.py
  ```

- فحص `verify_v41_ui.py` يظل مستقلًا لأنه يحتاج fixture ماليًا خاصًا ولا يُضم إلى الحزمة الذاتية كأنه قابل للتشغيل بلا تجهيز. مرور قارئ شاشة فعلي باقٍ في 07-B اليدوية، وليس نجاح حزمة Playwright بديلًا عنه.

### 08-D — smoke وCI

- **الحالة:** منفذة ومتحققة محليًا؛ أول تشغيل فعلي على GitHub متبقٍ قبل الإغلاق.
- أضيفت `.github/workflows/ci.yml` للتشغيل عند `push` و`pull_request` ويدويًا، بصلاحية قراءة المحتوى فقط وإلغاء التشغيل الأقدم لنفس الفرع.
- مهمة `smoke` تفحص صياغة كل PHP، وصياغة فاحصات Python، ثم تشغّل profile الآمن بلا قاعدة.
- مهمة `integration` تبدأ MySQL 8.4، وتنشئ إعداد CI غير سري وقاعدة باسم معزول، وتثبت المخطط والترحيلات، ثم تشغّل `profile=ci` وحزمة Chromium كاملة. الشبكة الخارجية معطلة صراحة داخل فحص تحديد المواقع لتفادي نتيجة متذبذبة.
- ثُبت اعتماد الاختبار في `requirements-test.txt`، ولا تعتمد الحزمة على خادم بدأه المطور يدويًا.
- **نتيجة المحاكاة المحلية بتاريخ 2026-07-20:** نجح PHP `22/22` من الفاحصات المؤهلة بعد تحديث فاحص المثبّت وإضافة فاحص مالي لـv45، ونجح المتصفح `5/5` على تثبيت معزول فارغ. تخطت البوابة خمسة تدقيقات تعتمد على بيانات تشغيل وفحص الاستعادة المدمّر بتصنيف صريح.
- أضيف smoke أداء بعد رحلات المتصفح، وشُدد بعد الموجة الثالثة إلى `20/8/8/8/40` استعلامًا للداشبورد/الأذونات/المصروفات/الفواتير/التقفيل، مع سقف HTML وصفر استعلامات أبطأ من 250ms. نجحت جولة fixture متوسط من خمس عينات.
- توسع payload الكسول الذي يتحقق منه المتصفح ليشمل كروت الفيزا ومسميات الإيصالات والمصروفات، لا الأذونات فقط. كشف الاختبار كذلك عدم توافق صفحة التقفيل مع قاعدة قبل v45 عند قراءة `rep_misc_expenses.is_visa`؛ صار الاستعلام يختار العمود عند توفره ويرجع للسلوك النقدي القديم قبل الترحيل.
- أضيف `verify_v45.php` داخل rollback: يثبت أن عهدة المندوب تخصم كاش الإذن وكاش النثرية وتسليم السائق فقط، وتستبعد الفيزا، بينما الخزنة لا ترى الفيزا ولا تسليم السائق، والمطابقة تعرض مبلغ الفيزا كمعلومة مستبعدة.
- توسع smoke الأداء ليتحقق وظيفيًا من أن خيارات الإدخال السريع تُجلب عند فتح الأداة فقط، وأن رسم النتائج محدود بـ120، وأن متابعة الأذونات لا تحمل أكثر من 48 بطاقة وتستطيع إيجاد إذن مفتوح عبر البحث الخادمي.
- بوابة الدمج المقصودة: فشل صياغة أو invariant مؤهل أو رحلة متصفح يعيد exit غير صفري ويوقف المهمة. لا ندّعي نجاح GitHub Actions نفسه قبل أول تشغيل بعيد.

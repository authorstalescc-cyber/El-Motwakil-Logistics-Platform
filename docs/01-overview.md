# 01 — نظرة عامة والمعمارية

## 1. مجال العمل

**شركة المتوكل لخدمات النقل والتخليص الجمركي** — شركة وساطة تعمل في:

1. **النقل (البوالص):** نقل حاويات/بضائع بالشاحنات نيابةً عن العملاء، مع محاسبة كل رحلة (نولون، مصروفات تشغيل، صافي السيارة).
2. **التخليص الجمركي:** استخراج شهادات وأعمال تخليص للبضائع الواردة/الصادرة.
3. **نقل المولدات:** خط عمل متخصّص لنقل مولدات لعميلين رئيسيين (**ايجي كول** و**الشجيع**).
4. **الفواتير الشاملة (شامل):** فوترة العملاء بالقيمة المضافة وحساب ربح الوساطة.
5. **الإصدارات (أذونات/شهادات):** أكبر عملية في نسخة الويب — دورة عمل كاملة بتايم لاين لكل إذن صادر أو شهادة وارد.

## 2. النظامان

### النظام (1): الإكسل — الأصلي

- سكربتات **Python** (openpyxl) **تُولّد** ملفات Excel جاهزة ومنسّقة ومليئة بالمعادلات.
- **المنطق داخل معادلات Excel نفسها** — Python بيبني الشيتات والتنسيق والمعادلات والقوائم المنسدلة والرسوم البيانية بس؛ المستخدم النهائي بيشتغل في Excel بدون أي Python.
- ملفان ناتجان مربوطان: **النظام الأساسي** + **التقفيل اليومي**.
- ماكرو VBA اختياري لأزرار وبحث وتصدير PDF.
- تفاصيل كاملة: **[03-excel-system.md](03-excel-system.md)**.

### النظام (2): الويب — الأحدث

- إطار **PHP MVC مكتوب يدويًا** (بدون framework خارجي، بدون Composer)، namespace واحد `App\`.
- **PDO/MySQL**، جلسة واحدة مشتركة (مستخدم `admin`).
- Server-rendered: كل الصفحات PHP templates تُلَفّ في layout واحد؛ لا يوجد SPA. التفاعلية = ملف JavaScript واحد (vanilla) + Chart.js منسوخ محليًا.
- **RTL عربي بالكامل**.
- يعمل على شبكة المكتب المحلية، يدعم أكثر من موظف في نفس الوقت.
- تفاصيل: **[04-web-architecture.md](04-web-architecture.md)** وما بعده.

> **العلاقة بينهما:** نسخة الويب تُطبّق **نفس معادلات الإكسل بالضبط** (موثّق صراحةً في docblocks لـ `Calc.php`)، مع إضافة قاعدة بيانات ووحدات أحدث. بيانات الإكسل القديمة تُنقَل لمرة واحدة إلى الويب عبر `export_old_data.py` + `install.php`.

## 4. المعمارية عالية المستوى لنسخة الويب

```
المتصفّح
   │  HTTP (GET/POST)
   ▼
public/index.php  ── Front Controller
   │  require app/bootstrap.php  (autoloader + App::boot() + Auth::start())
   │  يُعرّف كل المسارات على Router
   ▼
App\Core\Router::dispatch()
   │  يطابق (method + path) → "Controller@action"
   ▼
App\Controllers\XxxController::action()
   │  requireAuth() + requireCsrf() (للـ POST)
   │  يستدعي الموديلات والحسابات:
   ├──► App\Schema         (تعريف الكيان)
   ├──► App\Calc           (معادلات الحساب)
   ├──► App\Models\*       (منطق المجال: Bill, Permit, Metrics, ...)
   │        └──► App\Core\Database  (PDO/MySQL)
   ▼
$this->render('folder/view', $data)
   │  يلفّ الـ view في app/Views/layout.php
   ▼
HTML (RTL) + app.css + app.js (+ chart.umd.js عند الحاجة)
```

**النقاط المميّزة في المعمارية:**

- **لا يوجد middleware pipeline** — المصادقة (`requireAuth`) و CSRF (`requireCsrf`) تُفرَض **يدويًا داخل كل action**، مش مركزيًا في الراوتر. نسيان الاستدعاء = action غير محمي.
- **معماريّة مدفوعة بالبيانات (metadata-driven):** الكيانات الأربعة للإدخال (`bawalis`, `takhlis`, `generators`, `shamil`) مُعرّفة كلها في `Schema.php`، ويخدمها كنترولر واحد عام `CrudController`. إضافة/تعديل حقل = تعديل `Schema.php` فقط.
- **مصدر واحد للحسابات:** كل المعادلات المالية في `Calc.php`، وكل التجميعات/التقارير في `Metrics.php`.
- **إعدادات على مستويين:** إعدادات البنية والاتصال في `config/config.php` (ملف)؛ إعدادات العمل القابلة للتعديل من الواجهة (اسم الشركة، نسبة الضريبة، سنة التقارير، الرصيد الافتتاحي، إعداد التايم لاين) في جدول `settings` عبر `App::setting()`/`setSetting()`.

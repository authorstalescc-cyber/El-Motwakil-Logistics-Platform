# تقرير المرحلة 3 — تجربة المستخدم والوصول

التاريخ: 2026-07-15

## النتيجة التنفيذية

تم توحيد السلوك الأساسي للجداول والنماذج والتبويبات والنوافذ على مستوى البرنامج، ثم تطبيق التحسينات مباشرة على التقارير والإعدادات والمديونيات والدليل والصفحات المالية المتأثرة. الاختيار الحالي للصفحات الطويلة هو **Pagination** خفيف داخل المتصفح، مع الإبقاء على Pagination الخادم الموجود مسبقًا وعدم تكراره.

## ما تم تنفيذه

### 1. الصفحات والجداول الطويلة

- إضافة ترقيم مشترك للجداول غير المرقمة: 10 صفوف افتراضيًا على الهاتف و25 على سطح المكتب، مع خيارات 10/25/50/100.
- دمج البحث والترتيب مع الترقيم بحيث يعاد حساب الصفحات بعد أي بحث أو ترتيب.
- عدم إضافة ترقيم ثانٍ للجداول التي تستخدم Pagination من الخادم.
- إضافة حالة نتائج حية وأزرار تنقل قابلة للوصول، وحفظ حجم الصفحة المختار محليًا.
- تقارير الهاتف ذات الأعمدة المناسبة تتحول إلى بطاقات بعناوين واضحة لكل قيمة، بينما تبقى الجداول الأعرض داخل منطقة تمرير معلّمة وقابلة للتركيز.
- تصدير CSV أصبح يصدّر الصفوف الظاهرة حاليًا بصورة متسقة مع البحث والترقيم.

### 2. الهاتف وصفحة التقارير

- إصلاح التجاوز الأفقي العام في صفحة التقارير.
- إعادة ترتيب مرشحات التقارير وأزرارها والتبويبات على الشاشات الصغيرة.
- تحويل جداول التقارير المناسبة إلى بطاقات هاتف، وإضافة `data-label` تلقائيًا للخلايا.
- إصلاح بنية HTML غير سليمة في جدول التحصيلات بإزالة `tbody` مكرر.
- توحيد البحث داخل جداول التقارير مع طبقة الجداول المشتركة بدل وجود سلوك منفصل.
- تطبيق نفس معالجة الهاتف على تقرير العميل التفصيلي.

### 3. معيار النماذج والرسائل والحقول المطلوبة

- ربط التسميات بالحقول تلقائيًا عند غياب `for/id`، وإضافة تسمية وصولية احتياطية من عنوان الحقل أو اسمه.
- إضافة `aria-required` وعلامة مرئية موحدة للحقول المطلوبة.
- عند فشل التحقق: إضافة `aria-invalid` ورسالة خطأ موحدة مرتبطة بالحقل، وإزالتها بعد تصحيح القيمة.
- استبدال نوافذ `alert/confirm` الأصلية برسالة/تأكيد موحد داخل البرنامج.
- تعديل تأكيدات الحذف والعكس والإلغاء والحركات المالية لتستخدم نصوصًا وأيقونات وحالات خطر متسقة.
- إضافة API مشتركة للتنبيه والتأكيد للاستخدام في الشاشات التفاعلية، ومنها إغلاق الإدخال السريع مع بيانات غير مطبقة.

### 4. الوصول ولوحة المفاتيح والتركيز

- إضافة رابط «تجاوز إلى المحتوى» وتحديد مناطق التنقل والمحتوى الرئيسية.
- إعلان الصفحة الحالية في القائمة بـ `aria-current`، وإعلان حالة فتح/طي قائمتي الهاتف وسطح المكتب.
- توحيد التبويبات باستخدام `tablist/tab/tabpanel` مع `aria-selected` و`aria-controls` والتنقل بأسهم لوحة المفاتيح وHome/End.
- تطبيق ذلك على التقارير والإعدادات والمديونيات، وتحسين تسمية تنقل دليل الأطراف.
- النوافذ المنبثقة الآن تحتجز التركيز داخلها، تبدأ من زر آمن، تغلق بـ Escape، ثم تعيد التركيز إلى العنصر الذي فتحها.
- إضافة تسميات للأزرار الأيقونية وتوسيع حالة `focus-visible` للعناصر التفاعلية.

### 5. تبسيط التنقل وتوحيد النصوص

- «سداد العملاء» أصبح «تحصيلات العملاء» في القائمة والبحث لتطابق المصطلح المحاسبي المستخدم.
- «الوكلاء والشركات» أصبح «دليل الأطراف» لأنه يشمل أكثر من نوع طرف.
- توحيد عناوين ونصوص وأزرار التأكيدات، واستخدام أيقونة تحذير محايدة للإجراءات الحساسة بدل إيحاء الحذف في كل الحالات.

## التحقق المنفذ

- فحص صياغة جميع ملفات PHP وعددها 176: ناجح.
- فحص صياغة JavaScript: ناجح.
- 15 اختبار تفاعل بالمتصفح: ناجحة، وتشمل الهاتف، البحث مع الترقيم، التبويبات بلوحة المفاتيح، النوافذ والتركيز، ورسائل الحقول المطلوبة.
- فحص متصفح مستقل لتأكيد إغلاق الإدخال السريع مع بيانات غير مطبقة: ناجح، والبيانات لا تُتجاوز قبل تأكيد المستخدم.
- لا أخطاء JavaScript مرصودة في عينات الهاتف وسطح المكتب.
- اختبارات الانحدار: `verify_v29`، الإدخال السريع، إعادة تصميم التقفيل، سعة الحركات، الدمج القديم، و`verify_v31`: ناجحة.

## حدود المرحلة وما يستحق مرحلة لاحقة

- الترقيم الحالي داخل المتصفح مناسب للأحجام الحالية. عند وصول جدول واحد إلى آلاف الصفوف، الأفضل نقل البحث والترتيب والترقيم إلى الخادم أو استخدام virtualization حقيقي بدل تحميل الصفوف كلها.
- يلزم لاحقًا مسح WCAG آلي شامل مثل axe، ثم مراجعة يدوية بقارئ شاشة، وتدقيق تباين الألوان عبر كل الحالات والثيمات.
- توجد جداول مالية عريضة عمدًا؛ على الهاتف تُعرض داخل منطقة تمرير واضحة عندما يكون تحويلها إلى بطاقات سببًا لفقد المقارنة بين الأعمدة.
- يمكن في مرحلة أداء لاحقة إضافة مؤشرات تحميل/هياكل Skeleton للطلبات البطيئة وقياس Core Web Vitals على بيانات إنتاجية كبيرة.
